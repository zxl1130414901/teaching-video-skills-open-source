# 质量优先的执行与复用

用于多步骤制作、续作、恢复和局部修订。优化执行负担，不删教学内容、互动、素材或必要验收，不自行更换模型/推理设置。下面的复用指本地资料与产物，不是对服务端提示词缓存或套餐扣额的控制。

## 1. 先定位，再读取

先取当前交接、认可版本、产物清单和检查摘要，再确定本轮变更。状态至少指向：认可底稿/口播、当前工程/交付路径、已完成/正在运行/失败任务、版本/哈希和证据、下一步及停止范围。优先引用已有记录，缺失才补小状态文件，不重抄整份事实或所有检查。

- 同轮每份技能/参考只加载一次。续作只读本集完整认可稿、相关底稿及依赖、系列目录和本轮所需规则，不从原始对话重走已完成拆解。
- 新题或实质知识变化仍完整读本题有关材料。最小输入必须足以核对全部关键步骤与条件，不能只读标题、摘结论或漏掉用户纠正。
- 先查文件名/大小/目录或键，长规范和工程按章节、字段、场景ID定向读取。写/改代码前读真实涉及实现及调用边界。
- 已读规范版本未变且当前上下文或可靠交接保留了实际适用规则，可复用已读状态。版本变化、上下文缺失、规则不确定时补读对应完整内容；哈希只证明文件未变，不证明已理解。

## 2. 复用工程，按依赖失效

使用已验证的现成脚本与配置，执行无需先把完整源码载入对话。仅为新机制、缺陷或接口差异修改必要模块；先检查初始化行为，恢复工程不重新初始化覆盖已修复脚本。批准稿不因方便复用旧配音而改写。

复用证据必须绑定相关**输入/输出哈希、生成与校验脚本/模型/配置版本、规范版本**。不能只看文件存在、文件名、时间戳或旧passed；缺少依赖记录时补核或执行必要检查，不宣称安全缓存已具备。

| 变更 | 必须重新核对的边界 |
| --- | --- |
| 事实/口播/声音文本或参考/权重/参数变化 | 相关知识/各版讲解、受影响配音、实际ASR/字幕/时间轴及下游成片；声音正确不能由文本哈希证明 |
| ASR或数字正规化/剪辑偏移变化 | 转写与字幕文字/时序、char_times、依赖它的视觉触发及最终成片；未变化且证据充分的WAV不自动重生 |
| 布局/素材/字体/视觉参数或内嵌字幕变化 | 实际绘制/字形/遮挡/相关关键状态、最终视频与媒体/字幕验收；正确配音不自动重做 |
| 验证器/其配置变化 | 它检验的相关证据失效，按新版本运行；不无故重做未变生产产物 |
| ZIP成员/包字节变化 | 最终包清单/哈希、隔离解压实际执行及再生成结果；不能借旧运行报告证明新ZIP |
| 交付复制/入口/相对路径变化 | 副本媒体/资料完整性、实际本地链接及入口播放；原件未变的已绑定解码证据可引用 |

这些是影响边界，不是可删检查清单。新生成/改变的最终MP4仍查完整解码、实际音画时长、响度/峰值、字幕全文/数值/术语/同步、受影响视觉与实际播放/章节。按机制风险选择足够关键帧与动态中间状态，由模型实际查看语义/遮挡/推理连接；不能用脚本、生产者自检或固定帧数替代独立审查。最终教学包在空的隔离目录解压并运行，核对实际新生成结果，避免旧输出掩盖缺文件/未运行。

## 3. 核心演示、可播放粗版与最终验收

在批量制作前验证核心动态过程的素材和实现。实拍、代码动画、交互演示录制均按实际题目选择；缺核心演示时优先解决它，不能先生产整套静图再用转场充当完成。允许小步验证后复用工程，不为一个题材搭建无关平台。

粗版把已实现核心演示、临时声音与解释停顿放在同一条可播放时间轴中，交付实际文件及段落ID。用户选真人配音时按[声音工作流](voice.md)提供录音包，接收后以实录重排画面/字幕；AI配音路线无需等真人录音。尚缺输入只影响对应阶段，不冻结其他可独立完成的工作。粗版验收关注内容/节奏，不把低清渲染称为最终画质。

工程与技能版本分别记录。修改规范不会自动更新旧视频、旧渲染器或时间轴；制作新集时检查旧模板是否仍强制目录、累计笔记、固定版头或一秒完整过程，按本轮范围改相关实现，不能沿用旧模板后宣称符合新规范。

## 4. 冻结最终产物后验收

先完成本轮交付集合，再核验最终字节；不要无内容变化地重写稿件、重打包或反复生成阅读页。哈希/版本相同的已通过证据可引用，明确产生日期和本轮读取状态。验收后若重编码、重打包、迁移或改入口，按上表更新相关证据并绑定新文件；报告模板不能自动把旧passed复制到新输入。

现有工程若尚未实现强依赖复用、确定性打包或公共参数化管线，分别记为待实现。本规则不允许因为写了规范就声称代码已经支持它，也不为制作一集顺带重构所有工程。

## 5. 输出小摘要，详细证据落盘

常规工具只返回状态、数量、关键实测指标、失败项/定位、详情路径。完整日志、逐词ASR、布局/时间轴、代码与检查JSON留文件；先读摘要，失败或语义疑点再读相关完整区段。避免截断导致重读；不得用“没有输出”推断通过。

检查用现成确定性脚本完成机械项，模型负责机制/口播、证据适用性、真实图片/声音差异和成片语义。真实关键画面仍须查看，摘要不能代替目视或实际运行。

## 6. 最小充分分工与等待

有独立工作可并行时按明确职责委派。子代理得到任务/权限边界、当前路径、认可版本/知识或场景ID、必要原材料和用户纠正、必须保留项、验收职责及输出路径；可自包含时使用不携带整段历史的任务说明，不给每个角色复制全部旧对话。独立审查者获得原产物和标准，不先灌生产者的“已经正确”结论。

生产者做自身必要自检；审查者核对事实/语音疑点/实际成片；主代理验证最终字节与证据、风险边界和交付入口。不同职责需要的检查保留，相同输入/相同目的的已通过检查引用报告，不另写一套。反馈只给结果、失败定位、证据和限制，正文落文件。

长任务只由一名负责人等待/观察；其他角色完成独立工作后提交并结束，新的依赖就绪再恢复，不空等或互相轮询。原进程运行中不重复启动；优先状态变更/完成事件，必要查询按阶段退避，单次阻塞不超过60秒，继续必要进度沟通。不能为了少调用放弃运行失败的处理或未完成工作。

本地TTS/ASR/渲染耗时与对话token不同，优化模型加载/编码速度不能直接报为token节省。评估效率用去重响应数、输入/缓存输入、输出（推理包含其中）、工具输出及必要返工，注明范围；不把字符/文件大小当token，不把累计快照重复相加，不承诺未实测的整集节省比例。
